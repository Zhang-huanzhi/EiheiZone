## 前言

网页有点卡，据说开启 HTTP/3 可以缓解。v1.2 诊断已确认大陆到韩国源站存在高延迟和波动性丢包，本迭代尝试启用 HTTP/3，验证它是否能减少 HTTP/2 多路复用下的请求长尾，改善实际页面加载体验。

## 1. 目标

在保留 HTTP/1.1 和 HTTP/2 回退能力的前提下，让 Caddy 可以从公网接收 HTTP/3 的 QUIC 流量，并用同一大陆客户端、同一浏览器和同一批页面比较启用前后的协议与页面长尾。

本迭代验证的是用户端到端表现，不把 HTTP/3 协商成功直接等同于性能改善。

## 2. 本次范围

- 为 Caddy 容器增加宿主机 UDP `443` 映射；
- 在腾讯云防火墙放行入站 UDP `443`；
- 保留现有 TCP `80`、TCP `443` 和 `www.eihei.zone` 重定向；
- 检查宿主机 UDP 监听、Docker 端口映射、Caddy 容器状态和 TCP 回退；
- 用浏览器 Network 的 `Protocol` 确认页面、RSC、API 和资源请求是否协商为 `h3`；
- 按 v1.2 的页面集合采样并比较 P50、P95、最大值、失败率和长尾请求；
- 记录 HTTP/3 有效、无明显收益或不可用的实际结论。

## 3. 不做事项

- 不修改 `Caddyfile`，不新增应用层 HTTP/3 逻辑；
- 不修改前端、后端、API、数据库结构或 Alembic Migration；
- 不引入 CDN、EdgeOne、源站迁移或新的缓存规则；
- 不把 HTTP/3 协商成功作为性能改善证据；
- 不在未完成公网验证前声称已解决跨境网络问题。

## 4. 技术方案与候选选择

标准 `caddy:2-alpine` 默认支持 HTTP/1.1、HTTP/2 和 HTTP/3。当前 Caddyfile 不需要增加协议指令，关键缺口是 Docker 只映射了 TCP `443`。本迭代在 Caddy 服务中增加：

```yaml
ports:
  - "443:443/tcp"
  - "443:443/udp"
```

客户端无法使用 HTTP/3 时继续通过 TCP `443` 回退到 HTTP/2。云防火墙放行和生产部署不由仓库文件自动完成，必须在发布前由维护者手动执行并记录结果。

对比测试固定同一客户端、浏览器、页面和网络条件。部署前使用现有 HTTP/2 结果作为基线；部署后先确认 `h3`，再采样每条路径至少 20 次，重点观察 `3~10` 秒以上长尾是否减少。

## 5. 影响范围

| 范围 | 影响 |
| --- | --- |
| Caddy 公网入口 | 增加 UDP `443`，保留 TCP 回退 |
| 云防火墙 | 需要新增入站 UDP `443` 放行规则 |
| 页面协议 | 支持客户端协商 HTTP/3；不支持时继续使用 HTTP/2 |
| API、数据库、应用代码 | 无变更 |
| CI/CD | `docker-compose.yml` 属于非文档变更，PR 和合并到 `main` 都会运行完整 CI；合并后成功会进入生产部署 |

## 6. 验收标准

1. `docker compose config --quiet` 通过，Caddy 同时声明 TCP `443` 和 UDP `443` 映射。
2. 腾讯云防火墙已放行入站 UDP `443`，宿主机能看到 UDP `443` 监听，Caddy 容器运行正常。
3. 浏览器对 `https://eihei.zone` 的目标请求能够稳定显示 `h3`，或明确记录无法协商的原因。
4. 公共页、Family 页、Owner 页、RSC、API、图片和 `www.eihei.zone` 重定向均保持可用。
5. 启用后无新增 4xx/5xx、登录失败、图片加载失败、容器重启或 TCP `443` 回退故障。
6. 每条目标页面至少完成 20 次采样，并记录 P50、P95、最大值、失败率和长尾样本。
7. 根据同条件 HTTP/2 基线给出明确结论：
   - **有效**：稳定使用 `h3`，页面无回归，长尾有明确下降；
   - **无明显收益**：稳定使用 `h3`，但关键指标没有改善；
   - **不可用**：无法放行、无法协商 `h3` 或出现错误回归。
8. 后端、前端和 Deployment artifacts 三项 CI 检查全部通过。

## 8. 发布与回滚

该迭代修改 `docker-compose.yml`，不是纯文档变更。Pull Request 阶段运行完整 CI；合并到 `main` 后再次运行 CI，成功后由 Deploy workflow 更新生产环境。

若 UDP `443` 无法放行、HTTP/3 无法协商或出现页面错误回归，移除 UDP `443` 映射并重新部署。TCP `443` 必须始终保留，作为 HTTP/2 回退入口。

## 9. 遗留风险

- HTTP/3 可以减少 TCP 队头阻塞影响，但不能消除跨境 RTT 和丢包；
- 浏览器、运营商或中间网络可能不支持或限制 QUIC；
- 单次采样结果会受大陆出口、时间段和运营商路由影响；
- 即使 HTTP/3 协商成功，也需要端到端数据证明页面长尾实际改善；
- 云防火墙规则、生产部署和真实浏览器验收必须由维护者在服务器环境完成。

## 10. 验收结论

本迭代的部署目标已完成：生产 Caddy 已公开 UDP `443`，能够宣告并接受 HTTP/3，HTTP/2 仍可正常回退。浏览器已经出现过 `h3` 请求，证明 HTTP/3 路径可用。

当前不能据此断言 RTT 降低或页面长尾已经改善。HTTP/3 主要可能缓解丢包场景下 TCP 队头阻塞对页面请求的放大，实际收益仍受浏览器连接复用、代理/VPN 和运营商网络路径影响。后续应在固定网络条件下补做简化的 RTT、协议比例和页面长尾对比，并将结果补回本文件。
