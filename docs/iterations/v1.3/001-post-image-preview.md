## 1. 目标

修复 Post 图片缩略图使用 `object-cover` 导致电脑截图、手机截图和超宽图片被裁剪的问题。上传预览、列表预览、详情页和全屏查看统一保留原始宽高比，确保图片内容完整可见。

## 2. 本次范围

- 将共享 `PostImages` 缩略图展示策略改为 `object-contain`；
- 保留固定缩略图容器、网格布局和 `bg-muted` 背景，允许图片周围出现留白；
- 保持上传预览、列表、详情和 Dashboard 对共享组件的复用；
- 保持全屏查看的 `object-contain` 和现有键盘、触摸切换交互；
- 为横向电脑截图、竖向手机截图和超宽图增加回归测试。

## 3. 不做事项

- 不修改图片上传、压缩、鉴权、API、数据库或媒体存储；
- 不改变图片网格列数、缩略图容器尺寸或全屏查看交互；
- 不执行 Git 分支创建、提交、推送、合并、部署或产品 tag 操作。

## 4. 技术方案与候选选择

`PostImages` 是上传预览、Post 列表、Post 详情和 Dashboard 的共享展示组件。缩略图继续使用正方形容器，但图片改为 `h-full w-full object-contain`，由容器的 `bg-muted` 承载横纵比例不一致时产生的留白。全屏查看继续使用 `max-h-[90vh] max-w-[90vw] object-contain`，避免视口约束下裁剪。

没有选择动态改变网格行高或按图片比例改变容器，因为这会改变现有列表布局并使多图排列不稳定；完整显示只需调整图片适配模式即可满足验收标准。

## 5. 影响范围

| 范围 | 影响 |
| --- | --- |
| 上传预览 | 横图、竖图、超宽图完整显示，允许背景留白 |
| Post 列表与详情 | 复用同一 `PostImages` 组件，行为保持一致 |
| Dashboard | 共享组件自动继承完整显示策略 |
| 后端、API、数据库 | 无影响 |

## 6. 验收标准

1. 横向电脑截图在缩略图中完整显示，不裁掉左右内容。
2. 竖向手机截图在缩略图中完整显示，不裁掉上下内容。
3. 超宽图完整显示，缩略图允许显示背景留白。
4. 上传预览、列表预览和详情页使用一致的 `object-contain` 策略。
5. 全屏查看继续使用 `object-contain`，图片内容不被视口裁剪。
6. 现有 Post 表单、列表、详情和 Dashboard 回归测试保持通过。
