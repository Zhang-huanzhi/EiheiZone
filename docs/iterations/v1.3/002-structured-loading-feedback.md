## 1. 目标

针对海外源站高 RTT、丢包造成的 Next.js RSC 长尾等待，提供立即可见的结构化骨架屏和站内导航进度反馈，减少用户将等待误认为页面卡死的情况。

本迭代改善等待感知和页面稳定性，不承诺降低跨境网络的物理延迟。

## 2. 本次范围

- 新增公开区、家庭区、管理区可复用的结构化页面骨架屏；
- 将根级和分段 `loading.tsx` 接入骨架屏；
- 新增站内普通左键导航的顶部不确定进度条；
- 导航持续超过约 1.2 秒时显示“网络较慢，仍在加载”；
- 保留现有表单提交 pending 状态，不重构表单请求层。

## 3. 不做事项

- 不修改后端、API 合约、数据库、缓存策略或服务器 TCP 参数；
- 不伪造加载百分比，不将进度条解释为真实网络进度；
- 不执行 Git 分支创建、提交、推送、合并或部署。

## 4. 技术方案与候选选择

使用共享 `Skeleton` 原语和 `PageLoadingSkeleton` 变体，固定标题、导航、操作区和列表占位尺寸，降低 RSC 返回后的布局跳动。使用根布局挂载的客户端 `NavigationProgress` 捕获同源站内导航，通过 `usePathname` 变化结束反馈；外链、下载、锚点、辅助键点击和当前链接不触发进度。

进度条采用不确定动画而非百分比，因为客户端无法从 Next.js RSC 导航可靠推导真实完成比例。慢网络提示只用于辅助说明，不阻塞点击和内容交互；`prefers-reduced-motion` 下关闭动画。

## 5. 影响范围

| 范围 | 影响 |
| --- | --- |
| 首次加载和分段导航 | 显示结构化骨架，保留目标页面空间 |
| 站内链接跳转 | 顶部显示不确定进度，长尾等待显示慢网络提示 |
| 表单提交 | 继续使用原有按钮 pending 状态 |
| 后端、数据库、部署配置 | 无影响 |

## 6. 验收标准

1. 根级、公开区、家庭区、管理区 loading 组件均渲染带 `aria-busy` 的结构化骨架。
2. 同源站内普通左键导航立即显示顶部进度条。
3. 导航持续超过约 1.2 秒显示慢网络提示，导航完成后进度条和提示消失。
4. 外链、下载、锚点、辅助键点击和当前页面链接不显示进度。
5. 骨架屏与真实页面在移动端和桌面端不产生横向溢出。
6. 请求失败时现有错误边界仍可接管，进度反馈不会永久遮挡页面。

## 8. 遗留风险

该方案只改善等待期间的可感知性和布局稳定性，不能消除跨境公网高 RTT、丢包或 HTTP/2 队头阻塞。网络入口、EdgeOne、源站地域和静态资源 CDN 仍属于后续基础设施评估范围。
