## 1. 前言

用户在中国大陆直接访问部署于海外的 EiheiZone 时，Family 和 Owner 页面偶尔需要数秒才能完成刷新。本迭代通过五类测试建立当前生产版本的性能基线：完整浏览器端到端延迟、生产 API 只读低强度压力、生产 Next.js 页面 HTML 低强度压力、服务器资源监控和 PostgreSQL 查询基线，并回答：

1. 当前页面实际有多快；
2. 当前读取能力达到什么水平；
3. 慢主要来自公网路径、页面链路、服务器资源还是数据库。

本次只进行只读测量和代码审查。除测试账号登录、注销产生临时 Session 外，不创建、修改或删除业务数据，不修改应用、数据库结构、生产配置或部署状态。

## 2. 执行摘要

**当前最主要的性能瓶颈是中国大陆客户端到海外服务器的公网访问路径。Next.js 页面 HTML 链路还存在明显长尾，但数据库和服务器持续资源不足不是主要原因。**

| 结论项 | 实测结果 | 判断 |
| --- | --- | --- |
| 无代理完整页面体验 | 公共页面 P50 为 `0.73-0.78 s`；Family/Owner 页面 P50 为 `0.77-0.94 s` | 日常可用，长尾会造成明显等待 |
| 网络代理对照 | 十个共同页面无代理 P50 为代理开启时的 `1.81-2.52` 倍 | 公网路径是主要瓶颈 |
| 生产 API 读取 | 目标 5 RPS 档实测 `4.927 RPS`，890 请求零失败 | 当前安全基线约 5 RPS |
| Next.js 页面 HTML | 目标 3 RPS 档实测 `2.927 RPS`，528 请求零失败 | 当前安全基线约 3 RPS |
| 页面 HTML 目标 5 RPS | 实测 `4.137 RPS`，最大延迟 `10.561 s`，零失败 | 吞吐未达到 90% 门槛，不记录为通过 |
| 服务器资源 | 负载最高 `1.93`，可用内存最低 `804.5 MiB`，容器零重启 | 未见持续资源过载证据 |
| PostgreSQL | 约 `7.8 MiB`，代表性查询 `0.025-0.136 ms` | 当前不是主要瓶颈 |

本次低强度压力测试没有寻找系统崩溃点，因此结果是当前生产环境的安全读取下限，不是最大 QPS 或长期容量。

## 3. 测试范围与指标定义

| 测试类型 | 测试对象与方法 | 主要指标 | 能说明什么 | 不能说明什么 |
| --- | --- | --- | --- | --- |
| 完整浏览器端到端延迟 | 浏览器导航实际页面，等待 `document.readyState=complete` 后再等待 250 ms | Min、Avg、P50、P95、Max | 单用户完成一次页面加载的实际等待 | LCP、INP 及各网络阶段占比 |
| 生产 API 只读低强度压力测试 | 从客户端经公网访问生产 API，只执行读取请求 | 实际 RPS、P50、P95、P99、Max、失败率 | 生产 API 入口的读取能力与长尾 | FastAPI 容器内部纯处理时间、最大 QPS |
| 生产 Next.js 页面 HTML 低强度压力测试 | 从客户端经公网访问 `/family/posts`、`/owner/qas` 等生产页面入口 | 实际 RPS、P50、P95、P99、Max、失败率 | 服务端生成并返回页面 HTML 的能力 | 后续 RSC、图片、JS、CSS 请求和浏览器渲染 |
| 服务器资源监控 | 测试前、中、后采集系统与四个容器的聚合指标 | CPU、内存、Swap、负载、连接和重启 | 是否存在资源饱和或异常退出 | 长期容量和云平台小时级趋势 |
| PostgreSQL 基线 | 读取规模、连接、缓存命中、表统计及代表性执行计划 | 数据量、命中率、查询耗时 | 数据库是否足以解释当前等待 | SQL QPS、连接池等待和逐请求 SQL 数量 |

这里的“页面 HTML”是浏览器网络面板中的页面入口响应，不是项目 Markdown 文档。完整浏览器端到端测试和页面 HTML 压力测试是两类不同测量，不能互相替代。

两组压力测试都访问云端生产环境：

```text
生产 API：客户端 -> 公网 -> Caddy -> FastAPI -> PostgreSQL
页面 HTML：客户端 -> 公网 -> Caddy -> Next.js -> FastAPI -> PostgreSQL
```

因此 API 延迟包含客户端公网和 Caddy 开销，不等于 FastAPI 容器内部执行时间；页面 HTML 延迟也不能直接归因给 Next.js。

## 4. 环境、数据规模与方法

### 4.1 测试环境

| 环境 | 记录 |
| --- | --- |
| 客户端 | Windows 11 25H2，x64，Asia/Shanghai |
| 浏览器 | 同一桌面浏览器、同一代码版本；登录态由用户手动建立 |
| 生产主机 | 腾讯云 CVM，Ubuntu 24.04.4，2 vCPU、约 1.9 GiB 内存、1.9 GiB Swap、50 GiB 磁盘 |
| 生产架构 | Caddy、Next.js、FastAPI、PostgreSQL 四个容器 |
| 生产数据 | 8 条 Post、9 张 PostImage、3 条 QA、0 条 Expenditure |
| 正式基准网络 | 网络代理关闭，由用户确认；Windows 系统代理关闭，测试前独立检查 WinHTTP 为直连 |
| 网络对照 | 网络代理开启，由用户确认 |

代理开关只代表客户端代理软件状态。实际公网出口、代理节点、DNS 和运营商路由均为 `Not Verified`。

### 4.2 完整浏览器端到端采样

- 每条路径预热 5 次，再顺序采样 20 次；
- 无代理数据作为正式基准，代理开启数据仅用于网络路径对照；
- 页面时间包含客户端网络、Caddy、Next.js、后端取数、图片和浏览器工作；
- 所有正式页面样本均成功；本指标不是 Core Web Vitals。

### 4.3 低强度压力测试（受控负载）

- 使用 Locust `2.46.3` 和 Python `3.14.6` 临时执行，不向应用仓库增加依赖或测试脚本；
- API 和页面 HTML 分为两个场景，均按目标 `1 -> 3 -> 5 RPS` 运行，每档 180 秒，档间冷却 60 秒；
- API 场景覆盖健康检查、公开 Post、当前用户、Dashboard、登录态 Post、QA 和支出列表；
- 页面 HTML 场景覆盖 `/`、`/posts`，以及 Family、Owner 的首页、Post、QA 和支出列表；
- 使用专用 Owner 测试账号，每个虚拟用户先登录、结束时正常注销，全程最多 5 个临时 Session；
- 正式流量只发送 GET；登录和注销除外；
- 晋级要求为实际 RPS 达到目标 90%、错误率不超过 1%、无 5xx，且未触发资源保护条件；
- 连续 3 个 5xx，或完成 100 个请求后错误率超过 1%，自动终止；
- CPU 持续 60 秒超过 85%、可用内存低于 300 MiB、Swap 增加超过 100 MiB 或容器重启时停止。

首次页面 HTML 1 RPS 尝试只使用 1 个虚拟用户，实际形成 `0.887 RPS`，属于调度余量不足。该次结果不进入正式表；正式复测在目标 1/3/5 RPS 时分别使用 2/4/5 个 Session。

## 6. 低强度压力测试结果

本节所称“压力测试”是最高 5 RPS 的受控低强度读取，不寻找崩溃点，也不代表系统极限。

### 6.1 生产 API 只读场景

| 目标 RPS | 请求数 | 实际 RPS | Avg | P50 | P95 | P99 | Max | 失败率 | 结果 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | --- |
| 1 | 176 | 0.975 | 544 ms | 600 ms | 1.20 s | 1.20 s | 1.383 s | 0% | 通过 |
| 3 | 527 | 2.919 | 458 ms | 310 ms | 1.00 s | 1.50 s | 2.127 s | 0% | 通过 |
| 5 | 890 | 4.927 | 290 ms | 290 ms | 630 ms | 1.30 s | 2.301 s | 0% | 通过 |

三档共 1593 个正式请求，全部返回 200，无 4xx、5xx、超时或提前停止。5 RPS 档中 Dashboard、登录态 Post 列表和公开 Post 列表的平均延迟分别约为 `315 ms`、`340 ms` 和 `368 ms`。

**API 目标 5 RPS 档通过，当前安全读取基线至少为实测 `4.927 RPS`（约 5 RPS）。**

### 6.2 生产 Next.js 页面 HTML 场景

| 目标 RPS | Session | 请求数 | 实际 RPS | Avg | P50 | P95 | P99 | Max | 失败率 | 结果 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | --- |
| 1 | 2 | 180 | 0.994 | 672 ms | 600 ms | 1.50 s | 2.00 s | 2.640 s | 0% | 通过 |
| 3 | 4 | 528 | 2.927 | 669 ms | 570 ms | 1.50 s | 2.00 s | 2.433 s | 0% | 通过 |
| 5 | 5 | 754 | 4.137 | 826 ms | 600 ms | 2.20 s | 3.40 s | 10.561 s | 0% | 未达到吞吐门槛 |

目标 5 RPS 档没有业务错误，但实际吞吐只达到目标的 `82.7%`。最大请求来自 Family Post 列表，耗时 `10.561 s`；其他登录态页面也出现约 `3-5 s` 长尾。最多 5 个 Session 被长尾请求占用后，无法继续形成目标到达率。

**页面 HTML 目标 3 RPS 档通过，当前安全读取基线至少为实测 `2.927 RPS`（约 3 RPS）；目标 5 RPS 未验证通过。**

该结果不能推导服务器最大容量为 4.137 RPS：测试没有提高 Session 上限或寻找饱和点，服务器资源也未耗尽。它只描述“无代理公网访问、最多 5 个登录 Session、当前页面组合”下的实测边界。

## 8. 瓶颈归因

| 优先级 | 结论 | 证据 | 可信度 |
| ---: | --- | --- | --- |
| 1 | 中国大陆客户端到海外服务器的公网路径是主要瓶颈 | 代理开关同方法对照中十个页面全部同方向变化，P50 相差 `1.81-2.52` 倍 | 高 |
| 2 | 页面 HTML 链路长尾直接限制当前页面吞吐 | 目标 5 RPS 档仅形成 `4.137 RPS`，并出现 `10.561 s` 长尾 | 中；尚未拆分网络与服务端处理 |
| 3 | RSC、预取和图片请求可能进一步放大浏览器网络往返 | 代码与浏览器现象支持存在额外请求 | 中；请求数量尚未正式统计 |
| 4 | PostgreSQL 不是当前主要瓶颈 | 数据量小、缓存命中率高、代表性查询为亚毫秒、CPU 峰值低 | 高 |
| 5 | 服务器持续资源不足不是当前主要瓶颈 | 43.5 分钟监控未触发 CPU、内存、Swap、连接或重启保护条件 | 高 |

代码审查还发现 Post 图片关联存在 N+1 查询候选，Dashboard 包含多个列表和计数查询。这些查询形状需要后续优化，但当前没有证据表明它们主导本次端到端延迟。

### 9.2 Not Verified

- FastAPI 和 Next.js 容器内部的独立处理时间；

本地 SQL 查询数量实验因测试数据库隔离异常，未形成可靠结果。本报告不使用该实验判断 N+1 或逐请求 SQL 数量，相关指标保持 Not Verified。
