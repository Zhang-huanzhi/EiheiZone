## 前言

微信绑定成功后，通知设置页仍显示“生成绑定码”，且接口允许已绑定账户创建新码。绑定码只应服务于首次绑定或解除绑定后的重新绑定，因此这是一个状态约束缺失的缺陷。

## 1. 目标

- 已绑定微信的账户不能通过界面或 API 生成绑定码；
- 解除绑定后恢复生成能力；
- 用户在另一窗口完成绑定后，当前页面自动更新状态并清除旧绑定码。

## 2. 本次范围

- 在通知服务创建绑定码前检查当前用户的微信绑定，已绑定时返回 `409 WECHAT_ALREADY_BOUND`；
- 设置页仅在绑定状态加载完成且未绑定时显示生成操作；
- 绑定码展示期间每 5 秒轮询绑定状态，检测到绑定成功后更新为已绑定并隐藏绑定码与生成操作；
- 补充后端 API/服务测试和前端组件回归测试；
- 不新增数据库 Migration。

## 3. 不做事项

- 不支持绑定状态下直接换绑；需要先解除当前绑定；
- 不修改微信回调、通知 Worker 或 Outbox 数据结构；
- 不改变绑定码有效期和一次性使用规则。

## 4. 技术方案与接口

- `create_binding_code` 复用现有 `get_binding` 查询，在写入新码前抛出 `AppError(409, "WECHAT_ALREADY_BOUND", ...)`；
- 前端将 `null` 绑定状态视为加载中，不渲染生成按钮；冲突响应触发状态重新读取；
- 轮询只在绑定码存在时创建，组件卸载或绑定成功后清理定时器；轮询失败保留当前状态并等待下一次重试。

## 5. 影响范围

- 后端通知服务与 `test_wechat.py`；
- 前端通知设置组件及对应 Vitest 测试；
- V1.4 迭代索引。

## 6. 验收标准

1. 已绑定账户调用生成绑定码 API 返回 `409 WECHAT_ALREADY_BOUND`，且不创建绑定码记录。
2. 未绑定账户可以生成绑定码；解除绑定后可以再次生成。
3. 设置页加载状态期间不显示生成操作，已绑定状态只显示解除绑定操作。
4. 绑定码展示期间检测到绑定成功后，页面显示已绑定状态、清除绑定码并隐藏生成操作。
5. 后端通知测试与前端通知设置测试通过，且不需要数据库结构变更。

## 8. 遗留风险

- 轮询请求失败时，页面保留上一次已知状态，并每 5 秒继续重试；恢复通信后再更新绑定状态。
