## 1. 目标

验证父母关注微信测试号、绑定网站账号后，QA 和 Post 事件能够通过微信收到摘要和链接。测试号只用于 PoC，不作为正式长期通知渠道承诺。

## 2. 本次范围

- 一次性绑定码、微信 OpenID 绑定和解绑；
- 微信回调签名校验、关注欢迎语和绑定码文本处理；
- 新建 QA、新建 Post、首次回答 QA 的通知 Outbox；
- 独立 worker、发送重试、失败记录和重复事件唯一约束；
- 前端通知设置页和部署环境变量。

## 3. 不做事项

- 不发送 Post 或 QA 正文、图片和家庭敏感数据；
- 不通知 Post 编辑、删除或覆盖已有回答；
- 不开发站内通知中心；
- 不把测试号能力描述为正式生产通知渠道；
- 不执行 Git 分支创建、提交、推送、合并或产品 tag 操作。

## 4. 技术方案与候选选择

使用数据库 Outbox，让业务写入和待发送记录处于同一事务。worker 复用 backend 镜像，独立轮询待发送记录并通过微信模板消息接口发送；微信接口异常只影响投递状态，不回滚已完成的 QA/Post 操作。

网站生成短期一次性绑定码。用户关注测试号后，把绑定码发送给微信号，回调接口验证签名并把 OpenID 关联到登录用户。绑定码只保存哈希，使用后立即失效。

## 5. 验收标准

1. 测试号回调 GET 签名正确时返回 `echostr`，错误签名被拒绝。
2. 登录用户可以生成 10 分钟有效的一次性绑定码并查看绑定状态。
3. 关注测试号并发送有效绑定码后，网站显示已绑定；无效、过期或重复绑定码被拒绝。
4. 新建 QA 通知 Owner，首次回答通知提问人，新建 Post 通知所有已绑定家庭账号（包含作者）。
5. 微信消息只包含摘要和网站链接，不包含业务正文或图片。
6. 微信发送失败会重试，超过上限后记录为失败；重复事件不会重复入队。
7. `WECHAT_NOTIFICATIONS_ENABLED=false` 或未配置凭据时，QA/Post 正常提交。

## 7. 遗留风险

- 微信测试号用户上限和测试账号生命周期限制正式使用；
- 模板消息接口及消息场景规则需要在实际测试号后台和微信客户端确认；
- worker 依赖生产环境到微信接口的网络可达性。
