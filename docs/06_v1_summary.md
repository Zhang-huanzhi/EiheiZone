# EiheiZone V1 项目总结

## 1. 项目概述

EiheiZone 是一个面向家庭成员的私人信息门户，用于长期、结构化地分享生活近况、回答家庭问题和记录重大支出。项目同时承担完整 Web 工程实践的学习目标，从需求分析、架构设计、任务分解、编码实现、测试验证一直走到部署发布。

V1 面向三类角色：Public 可以查看公开内容；Family 可以访问家庭内容、提问和查看重大支出；Owner 负责发布、回答和管理。V1 明确不实现注册、即时聊天、文件上传、复杂搜索、通知、AI、完整记账和多语言，以控制范围并优先打通核心闭环。

## 2. 最终成果

V1 已实现 Auth、Post、QA、Expenditure、Dashboard，以及 Public、Family、Owner 对应页面和权限边界。系统采用 Next.js 16、React 19、TypeScript 与 Tailwind CSS 构建前端，FastAPI、Pydantic、SQLAlchemy 和 PostgreSQL 构建后端，数据库结构由 Alembic 管理。

生产环境使用 Docker Compose 编排 PostgreSQL、FastAPI、Next.js 和 Caddy，通过同一域名提供 HTTPS Web 与 API。除浏览器访问外，项目还提供 PWA 安装入口和 Android WebView APK，已完成家庭成员真机验收。

## 3. 六阶段执行结果

1. **需求定义**：确定产品定位、三类角色、45 条 P0 功能需求、非功能要求和 V1 边界。
2. **架构设计**：确定前后端职责、`Router -> Service -> Repository` 分层、数据库结构、API、页面和权限模型。
3. **任务分解**：将实现拆为 11 项线性任务，每项包含实施内容、学习重点和完成标准。
4. **编码实现**：完成核心业务、迁移、测试基础、前后端联调和多语言 README。
5. **测试验证**：45/45 P0 需求通过；后端 229 项、前端 79 项、Playwright 2 项通过；后端覆盖率 95%，前端行/语句覆盖率 62.69%。
6. **部署发布**：完成公网 HTTPS、生产账号验证、PWA、Android 包、真机验收和 VPS 重启恢复验证，最终状态为 Accept。

## 4. 关键工程取舍

- 后端统一负责认证、授权、事务和数据访问，前端的入口隐藏不替代后端权限校验。
- 使用服务端数据库 Session、HttpOnly Cookie 和双提交 CSRF，满足小规模家庭系统的安全基线。
- 金额使用十进制类型和 ISO 4217 货币代码，避免浮点精度问题。
- Dashboard 从现有业务表聚合，不为展示需求创建重复数据表。
- 采用模块化单体和单机 Compose，而非微服务、Redis、消息队列或 CI/CD，降低 V1 运维复杂度。

## 5. 遗留事项与风险

V1 接受生产依赖审计中的 3 个高危告警，并将兼容升级及回归转入后续维护。完整 Migration 降级再升级只允许在临时数据库补验。当前 PostgreSQL named volume 可以承受容器重建和正常重启，但不能覆盖 VPS 整机损坏；异机加密备份与恢复演练尚未建设。

这些事项均已显式记录并作出接受或暂缓决定，不影响本次家庭小范围交付，但在扩大用户范围或存储重要数据前应优先处理。

## 6. 项目复盘

本次 V1 的核心成果不仅是可运行的软件，也是形成了一套适合个人项目的轻量级闭环：五份正式阶段文档约束首次开发，代码、迁移和测试保存实现证据，后续迭代则以单份迭代文档驱动，仅在核心设计、数据库或重大架构发生变化时更新主文档或新增 ADR。

V1 至此结束。后续工作分为两条路径：日常运行维护用于处理依赖、安全和备份；V1.1 用于根据真实家庭使用反馈定义新的功能范围，不直接回填或扩张已冻结的 V1。
