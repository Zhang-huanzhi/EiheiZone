### 1.1 文档目的

本文档用于将已经确认的 V1 需求与架构设计转换为适合个人开发者执行的编码任务，作为第四阶段编码实现与进度确认的正式依据。

本文档重点回答以下问题：

- V1 应按照什么顺序实施；
- 每项任务需要完成哪些内容；
- 实施过程中需要理解哪些知识；
- 满足哪些条件后可以进入下一项任务。

本文档不重复展开已经在 `02_v1_design.md` 中确定的数据字段、API 契约和权限细节。实施具体任务时，应按需查阅对应设计小节。

### 1.2 编制依据

| 资料 | 用途 |
|---|---|
| `01_v1_requirements.md` | 确定 V1 功能范围、角色权限与验收标准 |
| `02_v1_design.md` | 确定数据、API、页面、模块、安全与运行边界 |
| `技术栈x1.md` | 确定前端、后端、数据库与部署技术选择 |
| `开发流程/确定x1.md` | 确定任务分解阶段的目标和正式产出 |

如本文档与正式需求或架构设计发生冲突，应先修正上游正式文档，再调整任务内容。

### 1.3 使用规则

本计划采用线性任务顺序，每次只实施一项任务。任务进度仅使用以下两种标记：

| 标记 | 含义 |
|---|---|
| `[ ]` | 未完成 |
| `[x]` | 已完成 |

当前正在实施的任务在标题后标记“← 当前”。遇到阻碍时，在当前任务下简要记录原因，无需引入额外状态。

每项任务统一包含“实施内容”“学习重点”和“完成标准”。实施时应先完成一个可运行的小步骤并立即验证，不应一次性创建全部后续文件，也不要求预先掌握所有后续技术。

## 3. 任务 1：建立 FastAPI 后端工程基础 

### 实施内容

- 检查 Python 3.14 和 `uv` 是否可用；
- 在 `eiheizone/backend` 初始化 Python 项目；
- 安装 FastAPI 及运行项目所需的最小依赖；
- 创建 FastAPI 应用入口和统一 Router 入口；
- 创建集中配置，统一读取和校验环境变量；
- 准备 `.env.example`、基础测试和后端 Dockerfile；
- 提供可由浏览器或 API 工具访问的最小响应。

本任务仅建立后端工程骨架，不连接数据库、不实现登录，也不创建前端工程。

### 学习重点

- `uv` 对 Python 项目、虚拟环境和依赖的管理方式；
- `pyproject.toml`、锁文件和 Python 解释器的职责差异；
- FastAPI 应用的创建、启动与请求处理过程；
- Python 包、模块、导入和 `__init__.py`；
- 集中管理环境变量的必要性；
- 基础自动测试的编写与执行方式。

### 完成标准

- [x] `eiheizone/backend` 可以通过 `uv` 安装，FastAPI 能启动并返回最小正常响应； ✅ 2026-07-21
- [x] 集中配置、`.env.example`、基础测试和代码检查可以正常工作，仓库中没有真实秘密； ✅ 2026-07-21
- [x] 能够说明 `main.py`、`api.py` 和 `config.py` 的职责边界。 ✅ 2026-07-21

## 4. 任务 2：建立 PostgreSQL 数据访问与迁移基础

### 实施内容

- 使用本机已经安装好的 PostgreSQL 服务；
- 创建彼此独立的开发数据库和测试数据库；
- 使用 SQLAlchemy 建立数据库连接和基础 Model；
- 建立请求使用的数据库 Session；
- 初始化 Alembic；
- 建立一份最小 Migration，并练习升级和降级；
- 为测试准备独立数据库，避免误改开发数据。

本任务仅建立数据库访问和迁移基础，不创建 User、Post、QA 与 Expenditure 业务表。

### 学习重点

- 数据库、表、行、主键和外键的基本概念；
- PostgreSQL 服务、数据库、账号和连接地址的关系；
- IDE 数据库工具与应用数据库连接的区别；
- SQLAlchemy Model 与数据库表的关系；
- SQLAlchemy Session 与登录 Session 不是同一个概念；
- Migration 与直接修改数据库结构的区别；
- 事务提交、回滚和连接释放的基本意义。

### 完成标准

- [x] 本机 PostgreSQL 服务可用，IDE 和 FastAPI 都能连接开发数据库； ✅ 2026-07-22
- [x] 开发数据库与测试数据库相互隔离； ✅ 2026-07-22
- [x] Alembic 可以从空库升级、合理降级，数据库异常时连接和事务能够正确清理； ✅ 2026-07-22
- [x] 能够说明 Model、数据库 Session 与 Migration 的区别。 ✅ 2026-07-22

## 5. 任务 3：建立统一 API 与后端测试基础

### 实施内容

- 为每次请求生成 Request ID；
- 统一 API 错误响应格式；
- 统一列表分页参数和响应结构；
- 建立后端测试的公共配置和测试数据准备方式；
- 测试常见的正常输入和错误输入。

本任务建立各业务模块共用的 API 与测试能力，不实现具体业务功能。

### 学习重点

- HTTP 请求、响应和状态码；
- `400`、`401`、`403`、`404`、`409`、`422` 的区别；
- Pydantic 如何校验 API 输入输出；
- Middleware 和异常处理器解决什么问题；
- `offset` 与 `limit` 分页机制；
- 单元测试与数据库集成测试的区别。

### 完成标准

- [x] `app/core/` 中的 Request ID、统一错误和分页能力能够正常工作； ✅ 2026-07-22
- [x] 正常输入、非法分页和字段错误都有可重复运行的测试，且不会污染开发数据库； ✅ 2026-07-22
- [x] 能够说明 Router、Schema、Middleware 与异常处理器的基本职责。 ✅ 2026-07-22

## 6. 任务 4：建立 Next.js 前端工程与 API 通信基础

### 实施内容

- 在 `eiheizone/frontend` 创建 Next.js 项目；
- 启用 TypeScript strict、Tailwind CSS 和基础 UI；
- 建立 Public、Family、Owner 页面目录骨架；
- 建立统一 API Client；
- 配置本地 `/api/*` 请求转发到 FastAPI；
- 创建一个最小页面并成功调用后端；
- 建立前端基础测试和生产构建。

本任务仅建立前端工程与通信基础，不实现正式登录和业务页面。

### 学习重点

- Node.js、包管理工具、`package.json` 和锁文件；
- React 组件、Props、状态和事件；
- Next.js App Router、Page 和 Layout；
- Server Component 与 Client Component 的基本区别；
- 浏览器通过 HTTP 调用 FastAPI 的过程；
- TypeScript、Tailwind 和组件测试的基本使用。

### 完成标准

- [x] `eiheizone/frontend` 中的 Next.js 可以启动，并通过统一 API Client 调用 `/api/v1`； ✅ 2026-07-23
- [x] Public、Family、Owner 路由区域以及加载、空数据和失败状态已经建立； ✅ 2026-07-23
- [x] 前端测试、类型检查和生产构建通过，浏览器构建结果不包含秘密； ✅ 2026-07-23
- [x] 能够说明 Page、Layout、Component 与 API Client 的职责。 ✅ 2026-07-23

## 7. 任务 5：实现认证、会话与后端权限

### 实施内容

- 建立 User 和 Session 数据表及 Migration；
- 使用 Argon2id 保存密码哈希；
- 实现安全的 Session Token、Cookie 和过期处理；
- 实现 CSRF Token 和 `Origin` 校验；
- 提供创建账号和重置密码的服务器脚本；
- 实现获取 CSRF、登录、退出和当前用户 API；
- 区分 Public、Family 和 Owner；
- 测试登录成功、登录失败、过期 Session 和角色不符。

V1 不做注册、找回密码和用户管理页面。

### 学习重点

- User、Cookie、Session 和浏览器登录状态的关系；
- 认证“你是谁”和授权“你能做什么”的区别；
- 密码哈希的作用与明文密码风险；
- CSRF 风险及 HttpOnly Cookie 的保护边界；
- `401` 和 `403` 的区别；
- Service 层承担权限与事务职责的原因；
- 数据库约束如何保护非法角色和状态。

### 完成标准

- [x] `app/modules/auth/` 和账号脚本支持创建账号、登录、退出、当前用户与密码重置； ✅ 2026-07-24
- [x] Session 过期与失效、CSRF、错误密码、Public/Family/Owner 权限均经过测试； ✅ 2026-07-24
- [x] Auth Migration 和测试通过，数据库与日志中没有明文密码或原始 Token； ✅ 2026-07-24
- [x] 能够说明认证、授权、Cookie、Session 与 CSRF 的区别。 ✅ 2026-07-24

## 8. 任务 6：实现登录页面与受保护路由

### 实施内容

- 创建登录页面和登录表单；
- 登录前取得 CSRF Token；
- 登录成功后按角色进入 Family 或 Owner 区域；
- 通过 `/auth/me` 判断当前身份；
- 保护 `/family/*` 和 `/owner/*` 页面；
- 实现退出操作；
- 处理未登录、无权限和 Session 过期。

### 学习重点

- 表单状态、字段错误和重复提交；
- Cookie 随浏览器请求发送的机制；
- Next.js Layout 对受保护页面区域的统一控制；
- 前端可见性控制与后端权限校验的职责差异；
- Redirect、Forbidden 和 Not Found 的区别；
- 前后端完成登录流程的协作方式。

### 完成标准

- [x] `src/features/auth/` 和对应页面支持登录、按角色跳转、当前用户和退出； ✅ 2026-07-25
- [x] Public、Family、Owner 访问错误区域以及 Session 过期时得到正确处理； ✅ 2026-07-25
- [x] 登录表单、受保护 Layout 和页面访问测试通过； ✅ 2026-07-25
- [x] 能够说明前端路由保护与后端权限检查的职责边界。 ✅ 2026-07-25

- 在后端查询中落实数据可见范围的必要性；
- `public` 和 `family` 两种权限范围；
- CRUD 和 PATCH 部分更新；
- 列表分页、详情和 Not Found；
- 前端表单与后端字段错误如何对应。

### 完成标准

- [x] `posts` 后端模块和 Migration 支持两种可见范围与 Owner 管理； ✅ 2026-07-26
- [x] 公开、Family 和 Owner 页面能够完成列表、详情、分页、表单和删除确认； ✅ 2026-07-26
- [x] Public/Family/Owner 权限、字段边界、Migration 和页面测试通过； ✅ 2026-07-26
- [x] 能够说明一次 Post 请求从页面到数据库再返回页面的完整调用过程。 ✅ 2026-07-26

## 10. 任务 8：实现 QA 家庭问答闭环

### 实施内容

- 建立 QA 表、Model、状态约束和 Migration；
- 允许 Family 和 Owner 查看全部家庭 QA 并提交问题；
- 新问题默认是未回答；
- 允许 Owner 查看问题并回答或替换一次回答；
- 完成 Family 区 QA 列表、提问页和详情页，允许 Family 与 Owner 提问；
- 完成 Owner QA 管理和回答页；
- 测试回答状态、角色权限和事务回滚。

V1 只支持一次提问和一次回答，不做多轮聊天、删除和私密问题。

### 学习重点

- 使用状态字段表达业务过程的方法；
- 回答内容、回答人、回答时间与状态的原子更新；
- 数据库 CHECK 与 Service 校验的双层保护；
- Family 和 Owner 在同一个资源上的不同操作权限；
- 写入失败时事务回滚的必要性。

### 完成标准

- [x] `qas` 后端模块和 Migration 支持 Family/Owner 提问、家庭查看与 Owner 一次回答； ✅ 2026-08-02
- [x] Family 和 Owner 页面完成，新问题及回答后的状态始终一致； ✅ 2026-07-27
- [x] Public/Family/Owner 权限、事务回滚、Migration 和页面测试通过，未加入聊天或删除； ✅ 2026-07-27
- [x] 能够说明状态一致性与事务回滚的重要性。 ✅ 2026-07-27

## 11. 任务 9：实现 Expenditure 重大支出闭环

### 实施内容

- 建立 Expenditure 表、Model、约束、索引和 Migration；
- 使用 Decimal 和 `NUMERIC(18,4)` 保存金额；
- 校验 ISO 4217 币种代码；
- 允许 Family 和 Owner 查看支出；
- 只允许 Owner 创建、编辑和删除支出；
- 完成 Family 支出列表和详情；
- 完成 Owner 支出管理页面；
- 测试金额精度、日期、权限和隐私字段。

V1 不保存银行卡号、完整流水号、详细地址、证件和附件。

### 学习重点

- 浮点数不适合保存金额的原因；
- Decimal、数据库 NUMERIC 与 API 字符串的协作方式；
- 时间点和业务日期的区别；
- 数据最小化与隐私保护；
- 硬删除、删除确认和失败回滚。

### 完成标准

- [x] `expenditures` 后端模块和 Migration 支持 Owner 管理及 Family/Owner 查看； ✅ 2026-07-29
- [x] Family 和 Owner 页面完成，金额精度与支出日期在数据库、API 和页面之间保持正确； ✅ 2026-07-29
- [x] Public 隔离、隐私字段、Migration 和页面测试通过； ✅ 2026-07-29
- [x] 能够说明 Decimal、业务日期与数据最小化的作用。 ✅ 2026-07-29
